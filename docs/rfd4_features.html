RFD4 features for SurPass

Which inputs can be used without a valid PDB structure? Source: RFD4-Proteina, SI Table S7 (pp.42–43), S2.1 (pp.32–37), S2.3 (pp.39–41), and S3.1 (pp.45–46). N is the padded token count; dimensions are RFD4’s published encodings, not proposed SurPass dimensions.

Start with connectivity and honest sequence-derived annotations.

Sequence identity, masks and chemical connectivity are available directly. SS, exposure, CATH and interaction labels can be supplied without a PDB at runtime, but RFD4 often obtains their training labels from structures. Replacing them with sequence predictions is an adaptation and should carry uncertainty. No new optional feature below has been adopted automatically; ResPair currently adds only the architecture and hidden-state recycling.

Outside the PDB-free shortlist

Absolute and internal atom coordinates/masks require supplied geometry; coordinate-group labels only describe the frames of that geometry. Generic atom identities and bond definitions can be obtained from sequence/chemistry, but resolved atom-presence patterns in the autoencoder training data are not guaranteed from sequence. RFD4 does not list MSA, PLM embeddings, or predicted per-residue SS/accessibility as its flow inputs; those would be SurPass choices.

Architecture already adopted

ResPair uses symmetric Hadamard single-to-pair updates, then PPLM-style inter/intra triangles, then a pair transition. Pair representations bias cross-attention. Optional hidden-state recycling adds projected prior states to the original embeddings. Intrachain triangle context is learned from sequence representations; this replaces PPLM’s structure-derived intrachain context. Triangle arithmetic scales cubically with chain length; chunking and checkpointing limit memory.
